# 03 · 数据格式

## 一、location 轨迹格式

GPS 轨迹点用 `@` 连接，每个点 8 个字段用 `;` 分隔：

```
lat,lng ; 毫秒时间戳 ; null ; null ; 速度m/s ; provider:精度 ; 航向 ; 标志
```

示例：

```
39.99409791809605,116.34441205951823;1792054177433;null;null;2.2;fused:1.2;78.0;1
```

| 下标 | 含义 |
|---|---|
| [0] | 经纬度 `lat,lng`（**GCJ-02**） |
| [1] | 毫秒时间戳 |
| [2][3] | 恒为 `null` |
| [4] | 瞬时速度（m/s） |
| [5] | `provider:精度`（`fused:1.2` / `gps:1.2`） |
| [6] | 约 `78.0`（航向，实测在 76~78 之间） |
| [7] | 标志位（`1` / `0`） |

> 真实抓包中约 5230 个点（约每 100ms 一个点）。本项目按约 5 米一个点生成，服务器接受。

## 二、datalog 日志格式

```
datalog = base64url( gzip( 跑步日志文本 ) )
```

跑步日志为原版 App 的调试日志结构，事件类型：

| 类型 | 说明 |
|---|---|
| `[LIFECYCLE]` | run_session_start / run_session_end |
| `[LOC   ]` | loc_point（GPS 点） |
| `[TRACK ]` | track_point_write（轨迹写入） |
| `[CHEAT ]` | 防作弊事件（如 `cheat_speed_too_fast_drop`） |

每行格式（示例）：

```
2026-10-15 16:53:23.05 [LOC   ] loc_point | reason=accepted_track_point, provider=fused, tsMs=1792054403051, accuracyM=1.2, gcjLat=..., gcjLng=..., isMock=false, pointNum=2225, stepFreq=0
```

> 服务器不深究 datalog 内容，本项目生成结构相似的最小日志即可通过。

## 三、坐标系

| 坐标 | 说明 |
|---|---|
| WGS-84 | OpenStreetMap / MapLibre 使用，本项目地图显示用 |
| GCJ-02 | 国测局加密坐标，高德 / 原版上传用 |

**上传前必须做 WGS-84 → GCJ-02 偏移转换**（北京偏移量约数百米）。

转换实现见 `app/src/main/java/com/rahab/dragonfly/util/CoordinateTransform.kt`。

## 四、速度换算

- 配速（min/km）→ 均速（km/h）：`speed = 60 / pace`
- 配速（min/km）→ 点速度（m/s）：`v = 1000 / (pace * 60)`

规则速度范围 `1.67-8.34 m/s` 对应 `10~2 min/km`，与 App 配速滑杆一致。

## 五、防作弊线索

- 原版日志含 `[CHEAT]` 事件：`cheat_speed_too_fast_drop`（速度过快掉点）。
- 每个点带 `isMock`、`provider`、`accuracyM` 等字段，服务器端有 `getRunPath.php` 可回查轨迹。
- **伪造轨迹时速度要落在规则范围内，否则可能被判定无效。**
